# S11: polygons straight to the GE

Where S10 left it, the busiest seconds of level 1 (PAL60, PPSSPP, `cpu_shift` 1) spent 318-332 ms
each in GPU DMA and GE drawing for ~72k polygons. Each polygon took the generic path: a `GpuPrim`,
`polygon()`'s clipping, `prim_begin`'s page and CLUT lookups, the state helpers, `sceGuGetMemory`
for its vertices and `sceGuDrawArray`.

## 1. The fast lane

`GpuRenderer` has a new member, `poly`: GP0 20-3F commands go to it straight from their words
before anything else. `rd_poly` in `ge.c` takes a polygon when:

- it has 3 or 4 vertices inside VRAM (no coordinate below 0, none past 1023/511);
- a textured one has a 4/8-bit page and no texture window.

Anything else (-1) takes the generic path as before.

A polygon whose **key** matches the one before is its vertices plus a few words of list. The key
is the command bits, texpage, CLUT, mask bits and drawing area that change the GE state. The vertices
go once into a 512 KB ring (partition 2, uncached, reset whenever the list has run). The list gets
BASE when it moves, VADDR and PRIM, per pass. Its state is left from the polygon before. The state
is still valid when:

- the key is the same;
- no tile changed;
- for a textured key, no tile under its page or CLUT turned newer on the GE.

## 2. State blocks

A key change costs a state setup. In the heavy seconds there are ~30k of them a second. Through
the helpers, each one was ~3 µs, almost all of it in sceGu calls writing uncached words.

Each key now gets a block of GE words:

1. The block is sent once, from a state forced unknown so that its words alone set everything:
   CLUT, texture, scissor, stencil, blend, dither, texturing, alpha test and VTYPE.
2. It is written into a 64 KB arena and ends in RET.
3. The list CALLs it (BASE + CALL).

When the key comes back within the same list, setting its state is those two words. The arena is
reset when the list has run, and a block's CLUT lives in that list too, so entries hold for one
list. The renderer's copy of the GE state is marked stale after a CALL and resent by the next
generic primitive. The two-pass draws (opaque texels, then semi-transparent ones) keep their pass
words in the entry and send them before each pass.

The cache has 128 entries, two-way: the entry used longer ago is replaced. In the heavy seconds,
94% of setups are found in it. Misses are mostly a key's first use in a new list.

| setup | cost |
|---|---|
| sceGu helpers (S10 path) | ~3 µs |
| block copied into the list | ~2.2 µs |
| block CALLed | ~0.6 µs |

## 3. Measured

Bench, 10 s from the same level snapshot (frame 7000, PAL60, `cpu_shift` 1):

| | S10 | S11 |
|---|---|---|
| speed | 99% | 99% |
| game fps | 58.4 | 58.6 |
| GPU poly ms, heavy seconds | 318-332 | 225-237 |
| draw ms/s | 187 | 153 |
| DMA2 ms/s | 199 | 163 |
| sleep ms/s | 184 | 213 |

~88% of polygons go through the lane. The rest are mostly ~9k per second with negative coordinates,
which `polygon()` clips.

Compare mode on the snapshot gives the previous runtime's differing pixels (46-51k per second,
8-10k more than one step). The frame 7300 shot renders as before.

The game fps no longer follows the host's load. Seconds that sleep ~290 ms still run at 99% speed
and 59 fps. The limit is the pacing: PS1 time against the host clock, at the PS1's NTSC rate
(~59.8 Hz) under the PSP's 59.94 Hz display.
