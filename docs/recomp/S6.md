# S6: sound and video

## SPU and XA (S6a)

Before S6a the runtime was silent: the SPU kept its registers and the CD dropped XA sectors.

- **SPU (`core/spu.c`):** 24 voices with ADPCM decode, Gaussian interpolation, pitch modulation,
  noise, the full ADSR, fixed and sweep volumes, ENDX, repeat addresses and the SPU IRQ. The IRQ
  is checked on block fetch, on capture writes and on transfers. Reverb runs at 22050 Hz and
  writes only when SPUCNT bit 7 is set. The CD input lands in the capture buffers (0x000-0xFFF).
  The mixing follows psx-spx; the structure is ported from RecompOne (MIT), with no reverb code
  taken from it.
- **Lazy timing:** the SPU catches up to `psx->cycles` (768 cycles a sample, at most one second)
  only when the game can tell: KON/KOFF and SPUCNT writes, reads of ENDX and of a voice's
  envelope or repeat address, and once per vblank. Each catch-up renders in voice-major chunks
  of up to 256 samples. A silent voice still walks its blocks, so ENDX, repeat and IRQ stay exact.
- **XA (`core/cdrom.c`):** an audio sector in a ReadS with mode bit 6 set is decoded (4-bit
  ADPCM, mono or stereo, 37800 or 18900 Hz) and resampled to 44100 Hz into a FIFO, which the
  SPU drains as its CD input through the CD volume matrix. 8-bit XA is logged once and skipped.
- **Host:** `PsxHost.audio` receives 44100 Hz stereo after each catch-up. On the PSP
  (`main.c`), a 16384-sample ring feeds a thread that owns one hardware channel and outputs
  blocks of 1024 samples. The ring drops input when full, plays silence when empty, and trims
  the backlog to about 70 ms when it grows past about 190 ms. The PC simulator writes the stream
  raw to the file named by `PSX2PSP_SIM_AUDIO`.

### Results (Sheep Dog)

- **Simulator (180 s up to level 1):**

  | Section | Level (RMS) |
  |---------|-------------|
  | Intro FMV (XA) | ~3-6k |
  | Menu music (XA, mode C0, no filter) | ~900 |
  | Level 1 (1-2 voices of SFX and ambience) | ~1-2k |

  The sample count matches the emulated time, with no clipping.
- **PPSSPP:**
  - Mixing cost: 87-122 ms per second, about 10% of the budget.
  - Level 1: still 100% speed with ~270 ms/s of sleep. No dropped samples and no gaps.
  - FMV (71-98% speed): the ring runs dry for a few blocks a second. This is the known MDEC
    cost, not the audio.

### Open items

- **Mixing cost:** idle voices still step through their blocks one sample at a time.
- **8-bit XA:** not decoded.

## FMV pictures and speed (S6b)

Before S6b the intro FMV played grey on the PSP and ran at 55-98% speed, while the simulator
showed it right.

- **The grey picture was a DMA bug, not MDEC.**
  - libpress sends two tables over DMA0 back to back: the quantisation table (0x40000001 plus
    32 words) and then the IDCT scale table (0x60000000 plus 32 words).
  - Native code reached the second start in fewer emulated cycles than the first transfer's
    length. The channel was still pending, so `dma_write` ignored the start.
  - The game then polled MDEC1 bit 29 in `DecDCTinSync`, timed out ("MDEC_in_sync timeout",
    2 s each, about 4 s at the intro start), and decoded every block with an all-zero scale table.
  - **Fix:** a start on a channel whose completion is still due completes the old transfer at
    once. Its words have already moved, and the new transfer runs.
- **Fast IDCT (`core/mdec.c`):**
  - When the uploaded scale table is the standard DCT basis (each entry within 2 of
    0x8000·c(u)·cos((2y+1)uπ/16)), the two exact matrix passes equal the textbook 2-D IDCT. The
    Loeffler-Ligtenberg-Moschytz factorisation then applies: 12 multiplies per 1-D pass instead
    of 64, with 13-bit constants and 2 extra bits between passes.
  - Columns and rows with only a DC term take a shortcut.
  - Any other table falls back to the exact passes. The choice is logged once.
  - **Host test:** 200,000 random blocks, 12.8 M samples.
    - 98.3% match the exact passes and 1.7% differ by 1; none differ by 2.
    - 58 samples (0.0005%) differ by 255. These sit on the 9-bit wrap, where a one-step
      difference on a value of ±256 flips the clamped result between +127 and -128. They only
      occur with coefficients far outside what a real stream carries.
- **Colour conversion:**
  - Each chroma sample converts its 2×2 luma group at once, with the same integer math as before.
  - The final clamp is a table lookup, signed or unsigned per the output mode.

### Results (Sheep Dog, PPSSPP)

| | Before S6b | After S6b |
|---|---|---|
| Intro FMV picture | grey | correct |
| FMV speed | 55-98% | 97-101% |
| MDEC time | (no real decode) | 190-360 ms/s |
| Intro start | ~4 s of MDEC timeouts | none |

The level 1 pad script still reaches gameplay (shot at frame 8000), as the simulator does.

### Open items

- **Overlay loads:** the frame of a level overlay load still runs 3.8 s/s interpreted. This is
  S5 work (native coverage for overlays and function pointers).
