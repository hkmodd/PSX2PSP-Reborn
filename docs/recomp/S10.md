# S10: the GTE's hot commands entered directly

Where S9 left it, in level 1 at PAL60 (PPSSPP, `cpu_shift` 1): 95% of PS1 speed, 55.5 game
frames a second. `psxrt.trace` bit 7 put the GTE first among the costs: ~250k commands and
350-380 ms per second. Every command went through one door (`psxrt_gte_cmd`): registers parked,
host stack, `native_gte_fast` in C, its dispatch, the command's function.

## 1. Entries of their own

The translator sends five commands to entries of their own instead of the door
(`layout::GTE_OWN`: an entry, a mask, a value):

| Command | Words | Entry |
|---|---|---|
| NCLIP | `w & 0x3F == 0x06` | `GTE_NCLIP` |
| AVSZ3 | `w & 0x3F == 0x2D` | `GTE_AVSZ3` |
| AVSZ4 | `w & 0x3F == 0x2E` | `GTE_AVSZ4` |
| RTPS | sf = 1, lm = 0 | `GTE_RTPS` |
| RTPT | sf = 1, lm = 0 | `GTE_RTPT` |

NCLIP and AVSZ read no other bit of the word; RTPS and RTPT with other sf/lm bits still take
the door. The emitted code is `sw ra,GPR31(k0); jal entry; nop`, against the door's
`sw ra,GPR31(k0); lui k1,hi; jal GTE_CMD; ori k1,k1,lo`.

Each entry is an 8-byte stub (`0x09A00FD0` to `0x09A00FF7`) that jumps to its routine in
`trampolines.S`. The routines are Allegrex assembly on the GTE registers at `layout::GTE`,
parking only the registers they use in CTX. They use:

- `madd`/`msub`/`maddu` on HI:LO for the 44-bit sums;
- `ins` to take bits 12-43 or 16-47 of the product;
- `clz` for the divide's normalisation;
- `seh` for the IR range tests.

RTPS/RTPT check that TR fits 31 bits, as `rtp_fast` in `core/gte.c` requires. When it does not,
they put everything back and go through the door with the canonical command word.
`psxrt_unr` is the divide's reciprocal table, which `native_init` fills.

## 2. Checked at every boot

Before installing the stubs, `native_init` compares each routine with `core/gte.c`'s
`gte_command` on 4096 random register sets per command:

- magnitudes are drawn at random, so the products fall both in range and out of it, every
  saturation and overflow flag is hit, and the divide overflows as well as divides;
- the whole GTE is compared, data and control.

On any difference, the log names the command and the first register that differs, and the stubs
go to the door instead (`psxrt_gte_*_door`). The log line on PPSSPP:

    native: GTE NCLIP/AVSZ/RTPS/RTPT in asm, 0 of 20480 checks differ

In the recompiler's differential tests, the harness's stand-in GTE treats a word with an entry of
its own as its canonical value, so the two CPUs agree. A new test sends every entry, two
commands through the door and one entry in a `jal` slot.

The oracle test on the real executables (`real_functions_match_the_oracle`) failed from S9 on: it
took S9's hooks for host calls of an instruction. The harness now hands a hook to the
interpreter, which runs the code the recipe replaces. The test passes again.

## 3. Measured

Bench, 10 s from the same level snapshot (frame 7000, PAL60, `cpu_shift` 1):

| | S9 | NCLIP/AVSZ | + RTPS/RTPT |
|---|---|---|---|
| speed | 95% | 96% | 99% |
| game fps | 55.5 | 56.6 | 58.4 |
| io ms/s (draw, SPU) | 233 (182, 72) | 232 (187, 73) | 219 (187, 75) |
| DMA2 ms/s | 193 | 196 | 199 |
| update ms/s | 123 | 118 | 131 |
| sleep ms/s | 37 | 48 | 184 |

Commands through the door fell from ~250k to ~135k per second with NCLIP/AVSZ alone. Their time
stayed ~350 ms: RTPT (~85k per second) was the weight. With RTPT in assembly, the host sleeps
184 ms of every second.

The busiest seconds of the level now run at 59 fps with no sleep: ~72k polygons per second, and
~310 ms each in GPU DMA and GE drawing. The light seconds sleep ~280 ms. The next cost is the
GPU path (packets to GE commands, texture and CLUT binds), then GPF and MVMVA (~26k and ~14k per
second, still through the door).

Compare mode on the snapshot gives the previous runtime's differing pixels (46-55k per second,
~9k more than one step). A frame of the level renders as before.
