# S0 — Feasibility: Sheep Dog 'n' Wolf (SLES-02895)

Verdict: **GO.** Every number below was measured on the game's 26 executables, its disc image
and Sony's POPS core (pops_01g.prx, firmware 6.61). The measuring scripts live outside the repo
(session scratch); the numbers and decisions are recorded here.

## 1. Code: statically recompilable

- 26 executables, 18 distinct images (ENDING = LEV00 = LEV01, FEND = SCENE, LEV02-05, LEV06-07,
  LEV09-10 are byte-identical). 4,305 distinct function bodies, 1.98 MB, cover all of them.
- Recursive descent plus prologue scan (`addiu`/`addi sp,sp,-N`) reaches 89% of all text bytes,
  with no invalid instruction on any path and no jump leaving its own text.
- All 985 switch jump tables (23,367 targets) are resolved statically.
- Open: 13,996 `jalr` sites (2,819 distinct; 72% vtable-like) and 26 `jr` through a loaded
  pointer. They need a guest-address -> translated-code table at run time, built from the
  40,602 discovered entries (9,170 pointer words in data point at them).
- **Load delays: no hazard in the whole corpus** (638,455 loads, 10,541 COP moves checked; the
  detector proven on a planted case). POPS does not emulate load delays either. The translator
  needs no load-delay handling for this game; it must still check every recipe's code and
  refuse to translate a hazard it does not handle.
- Surface: ~58K COP2 instructions in game code (GTE inline in the engine, not only libgte);
  29,443 game accesses through `lui 0x1F80` (the PS1 scratchpad); every hardware register access
  (366) is in library code; 50 `$k0/$k1` uses in game code (to inspect); BIOS calls A0/B0/C0
  listed in the measurement (A0.43 Exec loads the level executables).

## 2. Runtime surface: small

- PsyQ 1993-1997: libgpu (sys.c 1.140), libetc (intr.c 1.75), libcd (bios.c 1.86) everywhere;
  libspu, libds in levels; libpress (MDEC) only in SLES/LOADER/CREDITS. **No libsnd/libgs, no
  CD-DA tracks.**
- Disc access is libcd/libds only (CdSearchFile/DsSearchFile + CdRead/DsRead, double speed). An
  own XA module streams MUSICS.XA (7 stereo channels) and VOICES.XA (7 mono channels) with
  Setfilter/ReadS. Memory card and BIOS pad only in FEND/SCENE/WHEEL; levels read the pad
  through their own SIO driver (LEV00 0x8009A5D0), which the recipe replaces with a hook.
- GPU: flat/gouraud/textured triangles and quads, opaque and semi-transparent, raw-texture
  toggles, F polyline, TILE, SPRT8 (front end and credits); draw-mode words E1-E6. **No large
  sprites.** The game reads VRAM back (StoreImage in level code, 0x80073A98), so VRAM must stay
  CPU-readable.
- Decoders: XA ADPCM (37.8 kHz, 7-channel interleave), SPU ADPCM (VAGp, 1,433 samples), MDEC
  (4 STR videos + TITLE.BS), TIM.

## 3. How POPS maps a PS1 onto the Allegrex (proven in pops_01g)

- PS1 RAM at a 2 MB-aligned PSP address (0x09800000): one `ins a,base,21,11` turns any
  0x00/0x80/0xA0 address and its mirrors into a host address. Bit 23 separates RAM from the
  scratchpad, mapped with `ins a,base,10,22`.
- Hardware registers: a table of read/write handlers indexed by `addr & 0xff8`; constant
  addresses are bound at translation time.
- Indirect jumps: a flat table, one word per PS1 instruction, PC -> translated block.
- `$k0/$k1` are free for user code: the PSP kernel saves and restores them across interrupts and
  context switches (uofw `interruptman/start.S`, `SaveThreadContext` at 168/172); POPS itself
  keeps PS1 registers in them.
- GTE in integer code (`madd`, `min`/`max`, `clz`, a reciprocal table), registers in memory.

## Decisions for S2 (translator) and S4 (renderer)

1. **Identity register mapping.** PS1 GPR n is Allegrex GPR n, so most instructions are copied
   as they are. PS1 `$k0/$k1` (50 game uses) move to a memory context; Allegrex `$k0/$k1` become
   the translator's two scratch registers (safe, see above).
2. **Memory access:** the POPS `ins` mapping inline, about 3 instructions per load/store (POPS
   calls a helper). Addresses known at translation time (`lui 0x1F80` scratchpad, globals,
   hardware registers) are resolved then: scratchpad -> a fixed host block, I/O -> handler call.
   Pointers that may reach the scratchpad get the bit-23 dual path.
3. **Indirect calls:** a guest->host table per image (text size / 4 entries, ~0.7 MB for the
   biggest level), filled at conversion time; a miss is a translation bug, logged with the PC.
4. **Interrupts** (VSync callbacks, root counters): a pending-flag check at loop back-edges and
   at calls, so busy-wait loops on `Vcount` see the vblank. The cost is 2-3 instructions per
   back-edge.
5. **Overlays:** all 18 images translated at conversion time; BIOS A0.43 Exec switches the
   active image.
6. **Renderer:** PS1 VRAM (1024x512, 16-bit) lives in PSP VRAM and the GE draws straight into it.
   The pixel formats match (PS1 BGR555 + mask bit = GE 5551), textures and CLUTs are read from
   the same memory, and the four semi-transparency modes map to GE blend modes. The display
   area is copied to the PSP framebuffer each frame. 1 MB + two 480x272 buffers fit in the
   PSP's 2 MB of VRAM.

## Expected performance

POPS runs the heavy frame in real PS1 time: 25-31 ms (1.5-1.9 vblanks). Native, with ~1.5x
the instructions (memory access and dispatch overhead) on a CPU clocked ~10x higher, the game
logic takes an estimated 4-6 ms. The 60 fps budget is 16.7 ms. To be measured at S3/S5.
