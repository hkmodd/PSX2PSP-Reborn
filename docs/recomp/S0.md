# Recomp S0 — feasibility (Sheep Dog 'n' Wolf, SLES-02895)

Measured 2026-11-14 from the 26 executables of the PAL disc and from Sony's POPS
(`pops_01g.prx`, firmware 6.61). Three independent measurements: code discovery and ISA
surface (M1-M5), library/GPU/disc surface, and how POPS maps a PS1 onto the Allegrex.

## Verdict: GO

Nothing measured blocks an ahead-of-time translation. The direct control flow resolves almost
entirely and the reached code has no load-delay hazards. The hardware is touched only by
library code, which is the part the runtime replaces with HLE anyway. The known hard parts are
runtime work that POPS already does on the same CPU (GPU on the GE, GTE, XA/MDEC). The
translator does not have to solve them.

**Load-delay hazards in reached code: 0** in all 26 EXEs. Checked cases:
- a load followed by a read of its register;

The detector finds 4 load-use pairs when it scans LEV00 linearly, all in data.

### Libraries and hardware

- **PsyQ 1998 libraries:**
  - libgpu, libetc, libcd, libgte and libapi in all EXEs.
  - libds in all except SLES and CREDITS.
  - libspu in all except LOADER.
  - libpress (MDEC) in SLES, LOADER and CREDITS.
  - libcard in FEND, WHEEL and SCENE.
  - A direct SIO pad driver.
- **Not found:** libgs, libsnd and libmath.
- **GPU primitives:**
  - flat and gouraud triangles and quads, with and without textures and semi-transparency;
  - flat polyline;
  - free-size tile;
  - E1-E6 state words.
  - No sprites, plain lines or raw-texture codes.
  - One effect (LEV00 0x80073A98) reads VRAM back with StoreImage.
- **Disc:**
  - One MODE2 track, no CD-DA.
  - XA: VOICES 314 MB (7 mono channels) and MUSICS 57 MB (7 stereo), both 37.8 kHz.
  - 4 STR files (MDEC 320x256 with interleaved XA) and one MDEC still, TITLE.BS.
  - VAG samples (no VAB) and TIM images inside the level files.
- **EXE switching:** CdSearchFile, CdRead, then BIOS `Exec` (A0:43). Overlays are whole EXEs, all
  known in advance.

### POPS's mapping (read from pops_01g.prx)

| What | POPS |
|---|---|
| PS1 RAM | PSP 0x09800000. Address bits 21-31 replaced by `ins a0,a2,21,11` (a2 = 0x4C): every mirror, KUSEG/KSEG0/KSEG1, 2 instructions |
| PS1 scratchpad | PSP scratchpad 0x00013000 (gp + 0x3000) |
| Context | gp = 0x00010000 (PSP scratchpad): GTE registers, PC, spilled registers |
| Memory access | per-width helpers called with `jal`, a0 = address; a non-RAM access rewrites its call site to an I/O / scratchpad / BIOS helper (handler table at gp + 0x1000 indexed by `addr & 0xFF8`); inline RAM/scratchpad path for `$sp`-based accesses |
| Registers | at -> k1, v0-v1 a0-a2 -> s2-s6, a3 -> fp, t0 t1 -> s0 s1, t6 -> k0, sp -> s7, t2-t4 s0-s7 ra -> FPU $f20-$f31, the rest in context memory |
| k0/k1 | free for user code: the kernel saves and restores them (uofw interruptman start.S) |
| Load delay | at translation: if the next instruction reads the loaded register it is emitted first |
| Dispatch | direct-mapped table at 0x09C00000, one word per PS1 instruction; direct jumps patched to link blocks |
| GTE | one `jal` per command to integer Allegrex routines (VFPU for lighting/colour) |
| Timing | t9 = cycle down-counter, checked at block exits |

## Decisions for S1-S3

1. **Memory map** (PSP user partition, 24 MB on the PSP-1000):
   - PS1 RAM: 2 MB at 0x09800000, so POPS's two-instruction `ins` mask applies unchanged.
   - Dispatch table: 2 MB at 0x09A00000, one word per PS1 RAM word.
   - Runtime, translated code and buffers: 0x08800000-0x09800000 (16 MB).
   - S1 verifies that a native EBOOT can reserve these addresses at boot.
2. **Context and scratchpad as POPS:**
   - Context: gp = 0x00010000.
   - PS1 scratchpad at 0x00013000.
   - Game code's 57k scratchpad accesses come from a `lui 0x1F80` base, so they become direct
     scratchpad addresses at translation time, with no check.
3. **Registers:** POPS's assignment, k0/k1 included. t9 is no longer a cycle counter (no emulated
   timing), which frees it for one more PS1 register.
4. **Memory accesses:**
   - Game code (0 I/O accesses): the inline RAM/scratchpad mask on every access.
   - Library code: helpers.
   - Most library code with I/O is replaced by HLE anyway.
5. **Indirect jumps:**
   - Static: jump tables (bounded) and constant targets.
   - Everything else goes through the dispatch table: PS1 address -> translated entry.
   - A miss runs the built-in R3000A **interpreter** from that PC and logs it, so the address
     can be added to the recipe. This is the safety net for the 11% of the text never reached
     statically.
6. **Load delay:** the translator detects hazards and, like POPS, emits the consumer before the
   load; any case it cannot reorder fails the translation, never silently. Sheep Dog has none.
7. **Translation unit:**
   - Each of the 18 distinct images is translated whole at conversion time.
   - `Exec` switches to the next image's code.
   - Library functions are recognised by their masked body hash (222 bodies are common to all 18
     images) and replaced by HLE where the recipe says so.
8. **Timing:** real time.
   - VSync from sceDisplay vblank.
   - Root counters from the system timer: the game times its physics with counter 1 in hblank mode.
9. **GTE:**
   - First: one call per command to C routines in the runtime, GTE registers in the context.
   - Then: VFPU where profiling shows it matters.

## Risks (in slice order)

| Risk | Slice | Mitigation |
|---|---|---|
| Fixed addresses 0x09800000-0x09C00000 not free in a native EBOOT | S1 | partition allocation by address; else a 2 MB-aligned block anywhere and the mask's constant from it |
| Indirect calls to code never found statically | S3 | interpreter fallback + recipe entries from its log |
| PS1 textures (VRAM pages + CLUT) on the GE: texture cache, semi-transparency modes | S4 | the largest engineering item; POPS proves the GE can do it |
| VRAM read-back (StoreImage effect at LEV00 0x80073A98) | S4 | keep a PS1-layout VRAM copy for read-backs |
| XA ADPCM and MDEC decoding cost | S6 | same work POPS already does on the same CPU |
