# S19: the GE state outlives the list

## 1. What the S18c PSP log said

The S17 + S18c build ran on the real PSP (PAL60, `cpu_shift` 0):

| | S18 | S18c |
|---|---|---|
| level 1: speed | 67-86% | 83-97% |
| intro: speed | 74-95% | 78-95% |
| 3D scene: speed | | 64-68%, ~34k polygons a second |

In the 3D scene a polygon costs about 7.3 us. The parts:

- **The stall step.** The moves cost under 1 ms a second with either step. A polygon costs about
  0.5 us less with 8 KB than with 1 KB.
- **`fl_setup`: 57-100 ms a second.** In one second there were 5876 setups, 5184 of them found
  cached, so 692 were built again. There were also 455 CLUTs converted, 34 pages copied and 599
  readback checks. All of the cache was tied to the list: a CLUT lived in the list's own memory, and
  a state block lived in an arena that was emptied at every `ge_sync()`. Every key was built again
  once per frame. A key was also built again after every texture upload, because the upload changed
  the epoch.
- **The `io dma` figure is sampling noise.** It swings from 3 to 710 ms a second, while the DMA's
  own timing (all transfers timed) is a steady ~310 ms. The figure times 1 access in 16, and a
  transfer is one access among a dozen a frame, so it lands in a sample or misses it.

## 2. The CLUT pool

A converted CLUT now lives in a slot of a pool (`clut_pool`, 128 slots of 1 KB). The table is
two-way set associative, by a hash of the CLUT's key. A slot is used again while the stamp of its
tiles holds, across lists and across epochs.

A slot that the open list loads from (`used == ge.syncs`) is never written. When its CLUT must
change in that list, the CLUT goes into the list as before, and `ge.clut_slot` is -1. The log
counts these as `cluts N+M in list`.

## 3. The state blocks kept

Each fast-lane entry (256 now, two ways per set) has its own 64-word block in the arena. The block
is written only when no open list calls it (`blk`). Otherwise the state goes into the list once.

A **kept** entry is untextured, or its CLUT is in the pool. It outlives the list. Before its block
is called again, `fl_current` checks two things:

- the page slot and the CLUT slot still hold what the entry was built with: each slot's `ver` goes
  up whenever it is written;
- when the epoch moved, both stamps are still current.

A hit marks the page and the CLUT as used by the open list, so `page()` and `clut()` do not write
them under it. An entry whose CLUT is in the list lasts as long as that list and that epoch, as
before.

The stall step is now 8 KB, with no alternation.

## 4. Checked in PPSSPP

- **Level 1 bench:** 100%, 59 vbl, 58.9 fps. No CLUT is converted now (it was ~455 a second on the
  device). Setups found cached are 97-99%, against 88% before.
- **Compare mode** from `level1.snap`, 14 s, against the S18c `ge.c`: the same 45-61k pixels a
  second differ from the software rasterizer, second by second, to within 1.5%.

The real-PSP figures come from the next device run. Watch the `fast N (S setups M ms, C cached)`
and `cluts` parts of the `-- ge:` line, and the `-- gpu: poly` time.
