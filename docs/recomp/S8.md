# S8: disc patches and the PAL picture at 60 Hz (native)

## Disc patches in native mode

A native EBOOT gets the disc patches of POPS mode, in the same order: PPFs, PAL→NTSC, the
title's code patches (`fix`, `fps`, `60hz` switches), then the Infogrames loader CRCs. They are
applied to the disc the runtime reads and to the executables the translator sees
(`disc_executables(img, patches)`), so the translated code matches the patched code in RAM. The
POPS config does not apply to the runtime and is only logged.

## Display height

The runtime shows `vrange2 - vrange1` lines of VRAM from the display start (doubled when
interlaced), as the game programs them (`gpu_display_height`, shared by psxrt and the
simulator). Buffer spacing is not a height: Sheep Dog's levels draw 240-line NTSC frames into
buffers 256 lines apart, and a spacing heuristic left a black band under them.

## Why the game's own 60 Hz mode is not enough

Sheep Dog is one dual-standard build. Its `60hz` patch (boot flag byte 0x8001008C bit 0) runs
the US release's NTSC path. That path lays out the screens for 240 lines, but the PAL disc's
art is 256 lines:

- LOADER.EXE sets the display to 240 lines (`li v0,240` at 0x801104F4; PAL: 256) and draws the
  loading bar at y = 0xE1 + (PAL ? 0xE : 0). The PAL loading pictures (LEV*.EBS, 512×256) lose
  their last 16 lines, and the bar sits 11 lines above its frame.
- The PAL FMVs are 256 lines in a 240-line display: a stray line above them, and they are cut
  at the bottom.

On a PS1 or under POPS, NTSC means 240 lines of picture, so this is how the NTSC path really
looks with PAL art. The in-game Screen Centering option does not help either: it only moves the
vertical range.

## PAL60

The runtime keeps the game on its PAL path and gives it 60 vblanks a second:

- GPUSTAT stays PAL, so the game picks its 256-line layout, FMVs and loading screens;
- a line stays 2168 cycles, the PAL hblank rate. The physics step comes from root counter 1 in
  hblank mode, so game speed holds;
- a frame is 263 lines instead of 314 (`lines()` in `core/psx.c`), about 59.4 vblanks a
  second.

Result in PPSSPP (the Host's check): vrange 0x023-0x123, 256 lines everywhere, and the art,
the loading bar and the FMVs where PAL puts them. The game reaches ~31 fps in level 1.

### From the patch database to the runtime

- `pal60 = yes` in a `[game]` of the patch database (here SLES-02895/SLUS-01369) marks a game
  that keeps time with a timer and not by counting vblanks.
- `convert_native`: when the "60 Hz" switch is on for such a game, its `60hz` patches stay off
  (a patch chosen by name still wins), and the header gets `NATIVE_FLAG_PAL60`.
- Native DATA.PSAR version 4: the header grows to 0xD0 with a flags word at 0xC0
  (`psp/psxrt/README.md`). `disc_open` passes it on as `DiscInfo.flags`, and `main.c` sets
  `psx.pal60`. The log says `PAL60: a PAL picture at 60 Hz`, then `video mode PAL60`.
- Without `pal60`, or with the switch off, nothing changes. POPS EBOOTs are not affected: POPS
  keeps its own timing (see POPS below).

## POPS (RE, pops_01g of firmware 6.61)

- **Timing is set by the PAL bit of GP1(08h)** (word gp+0x3668, bit 11):
  - Half-line cycles (float): 0x448688CE = 1076.27 NTSC, 0x448779A7 = 1083.8 PAL (0x11484,
    0x126A0; full line at 0x12698).
  - Lines per frame, in half-lines: 525 + (0x6467 >> 8·interlace) & (0x81 − 2·PAL). That gives
    526 NTSC and 628 PAL, i.e. 263 and 314 lines (0x11438-0x11468).
  - A PAL pacing branch for real time: 0x11664 → 0x125A4.
- **A POPS PAL60 is therefore a POPS patch:** the line count without the PAL term, with the PAL
  half-line kept. It needs popsfs (our ARK plugin), per title, and a test on a real PSP. An
  EBOOT cannot carry it, since POPS runs Sony's code.
